# 德藏 · 曾振德副所長名片管理

繁體中文名片管理應用程式，集中使用同一個 Supabase 名片資料庫。前端使用原生 JavaScript 與 Node.js 靜態伺服器；無需 npm 安裝執行依賴，OCR 元件已隨專案提供。

## 啟動

需求 Node.js 20 以上：

```sh
cd /workspace/namecard
npm start
```

預設連接埠 3000，可透過 `PORT` 調整。執行 `npm test` 驗證資料、OCR 擷取及雲端傳輸邏輯。

## Supabase 設定（必要）

請依 [Supabase 設定說明](supabase/README.md) 建立專案、執行 [建表 SQL](supabase/schema.sql)、建立登入帳號及加入成員名單。尚未設定時，網站只顯示連線／登入畫面，不會將新資料存到 localStorage。

GitHub Pages 部署讀取 Repository Variables `SUPABASE_URL` 與 `SUPABASE_PUBLISHABLE_KEY`，讓所有裝置使用同一個專案。只可使用 publishable／anon 公開金鑰；不可使用 service_role 或 secret key。

## 功能與資料

- 授權成員登入後共用名片、照片與交流備註；新增、編輯、刪除與收藏直接寫入 Supabase。
- 搜尋、分類、重要聯絡人、最近新增與卡片／列表檢視。
- JSON 備份匯入匯出、vCard 下載，支援既有瀏覽器名片明確確認後搬移；不自動搬移示範資料。
- 同一名片的版本衝突會提示，避免不同裝置的過期編輯覆蓋；網路寫入失敗保留表單。
- 文字及照片在同一個 PostgreSQL 資料表；以成員名單與 RLS 控制存取。照片每張上限 3 MB，列表按需載入照片。
- 本機只儲存公開連線設定、登入 Session，以及未移除的舊名片備份。登入密碼不保存。跨裝置更新可手動重新整理，頁面閒置且可見時每 30 秒更新。

## GitHub Pages 部署

在 GitHub Settings → Pages 將 Source 設為 GitHub Actions。設定 Supabase Repository Variables 後，推送 `main` 或手動執行 Deploy contact manager to GitHub Pages。網站公開檔案由工作流程明確列出，不包含 SQL、測試或管理員憑證。

瀏覽器內現有名片不會因程式更新自動消失或上傳；請從原本儲存資料的相同瀏覽器與網址登入並搬移。若原資料在其他網址，先匯出 JSON，再在新網站匯入。

## 名片照片自動建檔

在「新增名片」上傳 PNG / JPEG / WebP 照片（最大 3 MB），即啟動繁體中文及英文 OCR，辨識姓名、職稱、機構、電話、電子郵件、地址；分類由機構名稱推估。完成後請逐欄核對再儲存。未辨識出的欄位留空，收藏及交流備註由使用者填寫。

辨識會保留人工輸入與修正。重新辨識或切換辨識版本後擷取，可更新同次編輯中尚未人工修改的自動填值；重新開啟既有名片時，既有資料會受到保護，如需替換某欄可清空後重辨。可展開「辨識原文與欄位確認」，修正原文後再更新辨識欄位。低解析度、傾斜、直排、反光或複雜版面可能造成誤辨，無法保證完全正確。

OCR 使用隨專案提供的 Tesseract.js 5.1.1 與 tessdata_best 4.1.0 繁體中文、英文浮點高精度模型，在瀏覽器 Web Worker 執行，不上傳照片。首次辨識需從本站載入約 30 MB 的辨識檔案；瀏覽器可快取語言資料。檔案來源及授權見 `vendor/ocr/README.md`。


### 辨識品質改善

- 自動放大小字（最高 3 倍、長邊約 2200 像素）、對比拉伸與深色底反相，保留彩色原圖作為另一版輸入。
- 分散文字與整體版面各辨識一次，綜合引擎信心及可擷取欄位數選擇結果；可從原文區切換另一版。
- 「左轉／右轉 90°」與「框選名片範圍」可排除桌面背景並修正拍攝方向；照片處理後重新辨識。
- 使用新語言模型快取名稱，避免瀏覽器沿用舊版低精度模型。
- 顯示引擎信心分數與低信心提示；此分數不等於實際辨識準確率，不應作為免人工核對的依據。

驗證涵蓋單元測試及 Chromium 實際圖片辨識。五張合成測試圖（小字、深色底、雙欄、輕度模糊、極小模糊文字）的五項欄位精確比對，由舊版 19/25 提升為新版 22/25；雙欄由 3/5 改為 5/5，極小模糊圖仍僅 2/5。這是有限的合成回歸案例，不能推論真實名片準確率。嚴重模糊、透視變形及直排文字仍可能需要重拍或人工修正。

合成回歸測試結果保存在 `docs/ocr-validation.json`。可在已安裝 Playwright 與 Chromium 的開發機器，啟動應用程式後執行 `node scripts/benchmark-ocr.cjs` 重現；預設使用 `/usr/bin/chromium`，可用 `CHROMIUM_PATH` 指定。若 Playwright 安裝於其他路徑，可透過 `PLAYWRIGHT_MODULE` 指定套件路徑。此檢查需較多時間與記憶體，不是一般使用所需；一般邏輯測試仍使用 `npm test`。
